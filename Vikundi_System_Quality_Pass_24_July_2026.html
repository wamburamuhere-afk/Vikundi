1. Members — all 327 now active and consistent

The 320 members imported from M-Koba were sitting as "dormant", so different pages disagreed on the count (Dashboard said 327, the Members list showed 7, the Users list showed 8). After a careful, backed-up, reversible update, all 327 members are now active — and every page agrees.

Before
Dashboard 327 · Members 7 · Users 8 · Dormant 320 — numbers didn't match anywhere.
After
327 active members across the Dashboard, Members list, Users, and Member Analysis. Dormant list empty.

2. Contribution Ledger — reads correctly now

Members' M-Koba savings are shown as an opening balance

The imported savings used to be filed under "Entrance" and measured against a full year's target, so every member showed a huge false deficit. They now appear in their own "Opening (M-Koba)" column and count toward each member's balance — carrying money in can only reduce a shortfall, never create one.

The "M-Koba Name" column is filled in

It was blank for everyone; it now shows each member's M-Koba name pulled from their imported records.

The target period is realistic

The "months" figure now reflects the months that have actually elapsed since a member joined — not a flat 12 — so the Target and Surplus/Deficit finally line up.

3. Two pages that looked empty were hiding data

PageWhat was wrongNow
Transactions Opened on "No transactions" — the date filter defaulted to the last 90 days, but the imported records are dated February. Shows the full history by default — all 524 transactions, paginated.
Contribution Ledger grid Opened on an empty month range, the "‹" arrow did nothing, and 327 members loaded with no pagination. Opens on the months that have data, the period arrows work, and the grid is paged (25/page).

4. M-Koba reconciliation — tidy

One leftover row still displayed a spreadsheet-corrupted reference ("3.75E+15"). It's a zero-value transfer row that never affected the tie-out, but it now shows a clean dash instead of the junk. The statement remains fully reconciled — every shilling accounted for.

5. Email & reliability

Email sending is now installable

The mail library (PHPMailer) had never installed on the server due to a file-ownership issue; that's fixed, so email can be switched on once the group's sending details are entered.

Full transparency: while fixing the email setup, a supporting library the site quietly relied on (the error-monitoring SDK) was removed, which briefly took the site offline. It was spotted and restored within minutes, and two permanent safeguards were added so it cannot happen again: the library is now formally declared, and the startup code was hardened to keep the site running even if a component is ever missing. No data was affected.

Where things stand

Every issue found in today's review has been fixed and confirmed on the live site. The member roster is clean and consistent, the money records read correctly and reconcile, and the pages that looked empty now show their data. The system is in solid shape for day-to-day use.

One open item is a treasurer's decision (not a defect): whether the monthly contribution target should be measured from each member's join date or from the group's original start date — worth a quick look at the live numbers before deciding.
