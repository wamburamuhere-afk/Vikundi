3What's new this round

Four modules, forty-three endpoints, all group-administration screens rather than financial ones — the treasurer's back office was already finished as of the last report.

Meetings

Schedule a meeting, take attendance, fine whoever missed it. Deliberately not a straight mirror of the web: attendance updates only the people you actually record, never silently marking everyone else absent the way resubmitting a full paper roster would.

Documents

Two features under one roof — a shared file library, and an in-app tool for writing letters, contracts and notices that get routed for signature. Signing supports several people signing one document in turn, each notified when it's their turn, with the group notified the moment everyone has signed.

Voting & Leadership Applications

A genuine secret ballot — the system can prove how many people voted and for whom in total, but there is no record anywhere, for any role including the Administrator, of which member cast which vote. Members apply to stand for a leadership position; a review committee approves or rejects each application, and an approval is what puts a name on the ballot.

Reports & Statements

The personal and group financial statements members are used to seeing on paper, in the familiar pension-book layout, now available on the phone — plus two summary reports for leadership covering the group's overall financial position and its membership makeup.

4Defects found in the existing system this round

The same pattern as every round so far: building each doorway means reading exactly how the web system enforces its rules, and that reading keeps finding places where it doesn't.

Any ordinary member could view the leadership-election review committee's entire workload. Every applicant's personal statement, their reasons for standing, who proposed them, and the committee's own private notes on each decision — visible to any signed-in member, for every election the group has ever run. Confirmed live, fixed the same day it was found, and re-verified live afterward.
Any group leader could delete another leader's confidential letter. The document writer's delete action checked only whether the caller could delete documents in general, never whether the specific document was marked private and belonged to someone else. A leader with ordinary delete rights could remove a private letter they were never permitted to even open. Closed to match the rule the edit screen already enforced correctly.
Two group leadership roles — secretary and treasurer — could run an election but not vote in it. The permission to manage elections had been granted correctly; the separate, narrower permission to cast one's own personal vote had not. Both roles can now vote like any other member.
A file-library delete button had no permission check behind it at all — only an ownership check (yours, or an administrator's). Currently harmless because every role that can currently upload a file also happens to hold delete rights, but a future, more limited role would have inherited a delete permission it was never granted. Closed regardless.
Two meeting endpoints could be read by any signed-in account, not just those with the meetings permission — a milder version of the same "logged in" vs. "actually allowed" gap found in earlier rounds. Both now check the real permission.
A membership-analytics report has been miscounting at least one real administrator account as an ordinary member since it was built — it checks an old free-text label on the account instead of the account's actual assigned role, and the two had drifted apart on at least one real account. Fixed to check the real role.
One new defect was introduced by this round's own work — and caught within fifteen minutes. The new document-library endpoints were built against the permission naming this project's own records call correct, which turned out not to match what the live systems have actually been running on for years. Every non-admin role was briefly locked out of the shared document library. Standard practice on this project is to check every new endpoint against the live server, under a real account, before calling it finished — that check is exactly what caught this, and it was corrected the same day, before this report was written.

5How the work is checked

Unchanged from every report so far, and still the standard every module is held to.

CheckWhat it means
2,141 automated testsUp from 2,007. Every change runs all of them before it can ship.
Every endpoint tried on the live sitePassing tests is not the standard. Each one is exercised against the running server, as every role, before being called finished.
Refusals tested as hard as successesThe leadership-application privacy gap and the document-permission mix-up were both found this way — by deliberately testing what a member or a wrong role should not be able to do, not just what they should.
New work is re-checked live after it ships, not just beforeThe document-library permission mix-up was caught by re-testing the round's own new endpoints against the live server immediately after deployment — the same discipline applied to the existing system was turned on this round's own code too.

6Demonstration site

Still running at demo.vikundi.bjptechnologies.co.tz, on its own database, and still the proving ground for every module before it ships: every defect above, and every one of this round's forty-three new endpoints, was verified there under real accounts — Administrator, Chairperson, Secretary, Treasurer and an ordinary member — before being called finished, including a full live run of an election from application through voting to results.
