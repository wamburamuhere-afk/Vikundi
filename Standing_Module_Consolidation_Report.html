Executive summary

The same money bug kept coming back on screen after screen — savings showing zero, false deficits, invented monthly targets. The cause: every screen re-did the contribution math its own way. This work put that math in one module and pointed every screen at it, so a fix in one place can’t be undone by a stale copy in another.

The problem

Each report computed member standing independently, and the copies had drifted. Two failures dominated:

  • Fabricated targets. Screens defaulted the monthly dues to ?? 10000 and the entrance fee to ?? 20000 when the group had set neither. This group has not set a fixed monthly, so every member was measured against an invented 10,000/month target and shown a deficit that does not exist.
  • Imported savings mishandled. Money carried in from M-Koba is each member’s opening balance. Some screens skimmed the entrance fee out of it, or billed a full 12 future months — so members who brought real savings appeared to have paid nothing.

Because the logic was copy-pasted, fixing the ledger did nothing for the dashboard, statement or profile — textbook whack-a-mole.

The solution — one module

includes/contribution_standing.php now holds the calculation once. Every screen calls it. The rules it encodes:

  • No fixed monthly ⇒ no target. An unset monthly means “save what you can” — no deficits until the treasurer sets a real figure. The moment they do, every screen adopts it at once.
  • M-Koba money is opening savings. Identified by its transaction markers, it always counts toward a member’s total and is never skimmed as an entrance fee.
  • Measured from each member’s own first contribution, counting only months that have actually elapsed — never billing the future.

Verification

  • Test suite: 1,183 tests / 2,959 assertions passing. New coverage for the module’s math and each screen’s wiring; existing tests updated to assert delegation rather than the old inline code.
  • Numbers on real data: 334 members; with the monthly unset the expected target is 0 across the board — zero false deficits (previously a deficit on nearly every member). Group Reports and the Dashboard KPI are now computed from the same rule, so they are identical by construction.
  • No database migration in any PR; purely calculation-layer changes.

Outcome: every screen that shows contribution standing now reads the same definition, and none show a fabricated deficit. The system is correct-by-default and armed — the day a real monthly is set, accurate targets appear everywhere at once.
